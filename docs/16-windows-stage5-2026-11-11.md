## S5-01：截图复制稳定失败（阻塞）

用户在 Chrome 合成页面明确点击复制时出现“写入位图失败”。自动像素检查得到剪贴板不包含可供 .NET 读取的图片，未保存或检查实际截图像素，无遮罩结论仍缺证据。

独立诊断程序 `gpui-stage5-tools/scripts/fixtures/repro-copy-image.rs` 链接现有 debug 依赖库，直接调用真实 `quickpick_platform::probe::copy_image`，使用 32×24 不透明合成红色图片。运行 `gpui-stage5-tools/bin/repro-copy-image.exe` 连续三次返回同一中文错误并以 1 退出；无需截图、Chrome、移动或缩放即可复现。未重编译、修改或替换 fix1 应用。

编码对照探针 `probe-bitmap-formats.rs` 的结果：

| 编码 | BMP 信息头字节数 / compression | 先写 CF_DIB | set_bitmap_with |
| --- | --- | --- | --- |
| RGBA32 | 108 / 3 | 是 | 失败 |
| RGBA32 | 108 / 3 | 否 | 失败 |
| RGB24 | 40 / 0 | 是 | 成功 |
| RGB24 | 40 / 0 | 否 | 成功 |

失败边界定位至现有 RGBA BMP 的 `clipboard_win::raw::set_bitmap_with` 转换路径，排除了必须依赖 CF_DIB 写入顺序或所有 GDI 位图均失败的假设。源码中 `copy_image` 使用 Rgba8 编码；clipboard-win 5.4.3 的转换函数只复制固定 BITMAPINFOHEADER 再传给 CreateDIBitmap，扩展头及位域掩码没有一并传递。这与 RGBA/V4 失败、RGB24 成功的对照一致。底层错误码在两个 RGBA 场景分别为 0/6，不能仅凭 LastError 判断原因。

原始结构化证据：`../target/gpui-candidate/gpui-stage5-reports/screenshot-copy-diagnosis.json`。建议后续修复在正确保留像素的前提下使用受支持的位图编码/写入路径，再对真实复制函数和 GUI 截图执行回归。本轮遵照复用现有产物要求，未应用修复，不能标记问题已解决。候选 EXE SHA256 仍为 `2D139FEBAF97A06BD5B604945FA1E578602DD256A21ADCE2B98C065B84AB3CF5`。

诊断探针用其自身合成小图替换了本轮截图剪贴板；不能将该小图的复制成功当作候选截图复制通过。Enter、文字提取及图片翻译的补充人工反馈和计数已取得，复制问题仍未修复。
