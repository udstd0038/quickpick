# QuickPick 安全与隐私规范

## 1. 基本原则

QuickPick 首版采用本地优先和最少保存原则。

默认不保存：

- 用户选中的文本。
- 用户截取的图片。
- AI 返回结果。
- OCR 提取结果。
- 翻译结果。
- 总结结果。

只保存：

- 应用设置。
- 加密后的 API Key。
- 必要的窗口状态。

## 2. AI 上传边界

只有用户主动点击以下功能时，才允许上传数据到配置的 AI 服务：

- 划词翻译。
- 划词总结。
- 截图文字提取。
- 截图文字翻译。
- 输入翻译（手动输入文本）。

禁止：

- 自动上传剪贴板。
- 自动上传截图。
- 自动分析用户屏幕。
- 后台静默调用 AI。
- 保存 AI 请求历史。

## 3. API Key 保存

API Key 不得明文保存到普通配置文件。

优先方案：

- 使用 Windows 本地凭据或 DPAPI 能力加密保存。
- macOS 使用系统 Keychain，text、vision、input 三个账户分别保存；普通配置文件不保存明文 Key。
- Keychain 只有 `NoEntry` 可作为未配置处理，访问拒绝、锁定或后端失败必须返回错误。删除直接调用删除接口，不先读取密码决定是否清除。
- Keychain 错误只向前端返回固定错误类别，不转发可能包含凭据或后端数据的任意错误详情；临时读取的密码及无效编码字节及时清理。

最低要求：

- 配置导出和日志中不得出现完整 API Key。
- UI 中默认隐藏 API Key。
- 错误信息不得泄露 API Key。
- 主窗口保存 API Key 时可以同步保存非敏感 AI 设置，但仍不得把 API Key 写入普通设置文件。
- Rust 内存中使用可零化字符串保存 API Key，避免普通 `String` 副本。

## 4. 日志规则

开发日志和运行日志都不得记录敏感内容。

禁止记录：

- 完整 API Key。
- 用户选中文本原文。
- 截图图片内容。
- AI 请求 payload。
- AI 返回全文。

允许记录：

- 功能是否成功。
- 错误类型。
- 请求耗时。
- 模型名称。
- 非敏感配置状态。

## 5. 剪贴板规则

划词读取可能需要临时使用剪贴板时：

- 剪贴板兜底默认开启以保持划词兼容，用户可在设置页关闭。
- 操作前尽量读取并保存原剪贴板内容。
- 获取选区后尽量恢复原剪贴板。
- 临时复制只允许在 UIAutomation 直接取词失败后作为兜底，不得优先覆盖剪贴板。
- 只有用户明确点击复制时，才允许覆盖剪贴板。
- 如果恢复失败，必须尽量避免二次破坏，并可提示用户。

macOS 剪贴板兜底另需满足：

- AX 直接取词优先；读取失败、复制超时或复制后无文本不能把旧剪贴板内容当作选区。
- 先等待触发键和修饰键释放，再模拟复制；输入监控不足以可靠查询按键状态时安全停止，所有注入失败路径都尝试释放 C 与 Command。
- 完整备份每个 item 的类型和原始字节，最多 16 MiB、64 个 item、每个 item 128 种类型；空板可恢复。文件承诺、无法完整读取或超出预算时不执行兜底。
- 恢复前先构造完整替换内容并检查 changeCount；检测到后续写入时不恢复，恢复写入失败不报告取词成功。系统没有原子 CAS，最后检查与写入之间的竞争风险保留实机验证。
- 快照只保存在可清理的内存字节容器中，不落盘、不输出到日志或序列化给前端。CI 只使用私有测试剪贴板和固定非敏感数据。
- 第三阶段已实现访问保护并通过对应代码与 CI 验证：macOS 15.4+ 可查询的策略为 `AlwaysDeny` 时，读取快照及注入复制前安全停止；`pasteboardItems` 返回 nil 且无法区分访问拒绝与空板时不能视为空快照，不能继续复制、clear 或恢复。真实访问策略仍待实体 Mac 验收，该要求不是已复现的事故结论。

截图复制时：

- `Alt+3` 只允许进入框选流程，不应立即覆盖剪贴板；托盘“区域截图”和主窗口截图按钮入口保持撤回。
- 只有用户完成框选并点击横条菜单“复制”后，才允许把所选区域图片写入剪贴板。
- 点击横条菜单“提取”或“翻译”不应覆盖剪贴板。
- 原生区域截图复制只允许在用户点击“复制”后写入剪贴板，不保存截图文件。

共享截图会话要求（第三阶段代码与 CI 已通过，实机待验收）：

- 用户主动触发截图时可捕获选定显示器，生成遮罩内的临时预览；预览与复制/AI 的裁剪复用同一次 RGBA 捕获，不在遮罩已经显示后再次读取桌面。
- 选区只使用当前会话的相对图像像素，校验会话身份、有效状态及裁剪边界；过期或其他窗口遗留的选区不能用于复制或上传。
- 取消、捕获失败、会话过期和再次截图需清理原图与选区；已取消的后台任务晚完成不能回填旧画面或触发后续操作。
- 预览数据仅在当前界面与内存中处理，不写磁盘、localStorage、日志或历史；预览不构成向 AI 服务上传的授权。

截图 AI 时：

- 只有用户完成框选并点击横条菜单“提取”或“翻译”后，才允许从当前截图会话裁剪所选区域并上传到用户配置的 AI 服务。
- AI 配置、Base URL、模型和凭据状态须在区域裁剪与上传前检查；配置不完整、凭据访问失败时先显示提示，不裁剪目标区域、不重新读取屏幕、不发起网络请求。用户已经主动打开的预览不等于 AI 请求已经开始。
- AI 结果只显示在当前结果窗口和内存状态中，关闭窗口或清空状态后不再保留；Windows 历史原生弹窗与现行共享 WebView 窗口遵循相同内容生命周期。
- 翻译结果弹窗切换源语言、目标语言或方向时，只复用当前弹窗生命周期内的原始文本或截图字节重新请求，不把文本、截图或结果写入历史文件。
- 输入翻译弹窗切换语言或方向时，只复用当前弹窗生命周期内的输入文本重新请求，不把输入文本或结果写入历史文件。
- 开发日志不得记录 OCR 原文、翻译结果或截图内容。

## 6. 本地文件规则

首版不保存截图文件。

临时文件原则：

- 能在内存处理就不落盘。
- 必须落盘时使用系统临时目录。
- 完成后尽快清理。
- 不把临时图片放入项目目录或用户文档目录。

第四阶段开发工具的固定样例导出单独约束：README 截图工具只能保存隔离 `quickpick-fixture` 自己窗口的客户区，内容与 RGBA 均为固定非敏感样例。窗口必须使用不透明背景并关闭玻璃效果，仅用 `PrintWindow` 读取 owned 窗口，不以桌面捕获兜底。不得捕获用户文档、通用剪贴板或已运行的 QuickPick 窗口，不读取真实设置或凭据，不发起 AI 请求，也不写入真实启动项。`dev-tools` 不进入默认发行构建；工具在启动前拒绝无 fixture 标记的程序，启动后核验隔离路径及随机 token 的 loopback 控制接口。导出目标和运行模式由开发者明确指定；这不改变正式应用不保存截图历史的规则。退出时仅关闭工具创建的进程并清理 fixture 临时目录，不按进程名称结束其他实例。

## 7. 网络请求规则

AI 请求必须：

- 只使用用户选择的供应商和配置。
- 使用用户配置的 `base_url`。
- 使用用户配置的模型。
- 设置请求超时。
- 只发送完成当前功能所需的最小内容。
- 对错误做清晰提示。

不允许：

- 遥测。
- 未经说明的第三方请求。
- 自动更新前静默下载大文件。
- 外部 AI 服务使用明文 HTTP。

供应商默认值规则：

- 文本模型和视觉模型分别保存供应商、Base URL、模型名称和 API Key。
- 输入模型独立保存供应商、Base URL、模型名称和 API Key；输入翻译只使用输入模型配置，不复用或回退到文本模型/视觉模型配置。
- 选择 DeepSeek、小米 MiMo、Kimi、GLM、MiniMax 或 Qwen 作为文本模型时，应用可以提供默认 Base URL 和默认模型，减少手动配置错误。
- 选择 DeepSeek、小米 MiMo、Kimi、GLM、MiniMax 或 Qwen 作为视觉模型时，应用可以提供默认 Base URL 和默认模型。
- 用户手动填写 Base URL 后必须以用户填写值为准。
- 小米 MiMo 的 `tp-` Key 在未手动填写 Base URL 时可自动使用 Token Plan 默认地址。
- 旧版单 API Key 只兼容迁移为文本模型 Key；视觉模型 Key 需要单独保存，避免旧文本模型配置直接调用视觉接口。
- AI 响应体上限为 2 MiB，超过上限立即停止解析。

## 8. 权限与系统集成

QuickPick 需要的系统能力：

- 全局快捷键。
- 托盘常驻。
- 开机自启。
- 读取当前选区。
- 剪贴板访问。
- 截图。
- 默认浏览器打开搜索。

实现时应尽量使用 Tauri 官方插件和 Windows 标准能力，不做注入式或高风险全局行为。

macOS 权限引导要求（第三阶段代码与 CI 已通过，实机待验收）：

- 辅助功能、屏幕录制与输入监控分别查询；挂载或回焦复查不触发授权弹窗，也不访问用户内容。
- 授权请求由用户明确点击对应动作触发，请求返回后重新查询实际状态；拒绝、撤销、查询失败不得当作已授权，不反复自动请求。
- 打开系统设置仅使用 Rust 端按权限类别固定映射的 Privacy URL，不接受前端传入任意 URL、shell 命令或路径。
- 状态只用于当前权限引导，不写入内容日志、不绕过系统 TCC、不因授权返回自动复制、截图或上传；授予权限后由用户重试功能，需重启时提供提示。

WebView 与窗口权限：

- 启用严格 CSP，不保留 `csp: null`。
- 不使用 `core:window:default` 等宽泛权限，只声明实际需要的窗口权限。

## 9. 第三方代码边界

截图模块允许参考 Snow Shot 可用实现，但必须遵守：

- 引入前确认目标 commit 的许可证和文件来源。
- 保留必要的版权和许可证声明。
- 许可证不清楚时只做等价重写，不复制源码。
- 不引入超出 MVP 的滚动截图、标注、贴图、历史记录、录屏或插件代码。
- 参考项目代码不得改变 QuickPick 的隐私默认值：不保存截图历史、不自动上传截图、不记录截图内容。

## 10. 用户可控

设置页必须让用户能：

- 修改或关闭开机自启。
- 修改快捷键。
- 修改 AI 配置。
- 清除 API Key。
- 理解“不会保存历史”的默认策略。

开机自启只使用当前用户级启动项，不要求管理员权限；关闭后应删除 QuickPick 对应启动项，不保留额外后台计划任务。

## 11. 安全验收

首版验收时必须确认：

- `pnpm security:audit` 通过生产 npm 依赖审计和 `cargo audit`。
- 配置文件中没有明文 API Key。
- 开发日志中没有用户内容。
- AI 功能只在用户点击后触发。
- 关闭结果弹窗后不会保留可见敏感内容。
- 程序退出后不残留截图临时文件。
