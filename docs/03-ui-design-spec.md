# QuickPick UI 设计规范

## 1. 设计目标

QuickPick 的 UI 应该像一个安静、轻快的 Windows 11 原生工具。

关键词：

- 轻量。
- 克制。
- 快速。
- 清晰。
- 不打断当前工作。

不做营销式首页，不做大面积装饰图，不做厚重卡片堆叠。

## 2. 视觉基调

首版优先支持：

- Windows 11 Mica 背景。
- 暗黑模式。
- 跟随系统主题。

降级策略：

- Mica 不可用时使用半透明深色或浅色背景。
- 所有文字和图标必须在降级背景上保持可读。

字体：

- 软件自绘 UI 统一参考 TieZ Frosted Glass 字体栈：`"Segoe UI", "Inter", "Microsoft YaHei", sans-serif`。
- Web 设置页使用完整 CSS fallback；原生 Win32 弹窗使用 `Segoe UI` 绘制，并依赖 Windows 字体链接回退中文。
- 等宽场景如后续日志、代码或调试文本优先使用 `"Cascadia Code", "Consolas", monospace`。
- 不得在设置页、划词菜单、截图菜单、结果窗口之间混用明显不同的字体家族。

## 3. 划词横条菜单

触发方式：

- 用户选中文本后按 `Alt+2`。

位置：

- 优先显示在当前鼠标位置附近。
- 避免超出屏幕边缘。
- 不遮挡太多内容。

形态：

- 横向工具条。
- 不显示左侧读取状态和选中文本预览，首屏只保留操作按钮。
- 无边框。
- 置顶。
- 失焦隐藏。
- 轻微阴影或柔和边线。
- 外框使用圆角矩形，避免方形硬边。
- 视觉应向设置页浅色 Frosted Glass 靠拢：浅玻璃底、圆角按钮、柔和边线。
- 菜单必须跟随软件主题：浅色使用蓝白 Frosted Glass，深色使用设置页同款中性煤黑玻璃，不允许在深色主题下继续显示浅色菜单。

按钮：

- 复制。
- 翻译。
- 总结。
- 搜索。

按钮应使用图标加短文本，或在空间不足时使用图标并提供 tooltip。
按钮样式和微交互应与设置面板按钮一致：所有按钮使用统一浅色玻璃按钮样式，不单独突出“复制”；Hover 只改变颜色/阴影，Pressed 只在按住期间轻微居中缩小和加深颜色，松开后复位，不产生滑动位移。

状态：

- 默认。
- Hover。
- Pressed。
- Loading。
- Disabled。
- Error toast 或结果弹窗。

## 4. 截图遮罩

触发方式：

- 用户按 `Alt+3`。

要求：

- 覆盖可截图区域。
- 显示半透明遮罩。
- 拖拽时显示选择矩形。
- 选择区域边缘清晰。
- 显示区域尺寸信息。
- 支持 `Esc` 取消。

首版可以不做窗口智能识别，但拖拽框选必须稳定。

安全要求：

- 截图遮罩在恢复 `Alt+3` 前必须先通过开发入口验证。
- 开发入口必须使用普通窗口，保留系统标题栏和关闭按钮。
- 遮罩必须至少支持 `Esc`、窗口关闭事件和托盘退出三种退出路径。
- 不允许在未验证前直接开放置顶全屏遮罩热键。
- 如果普通开发窗口也出现白屏或无法关闭，必须撤回入口并先排查窗口加载链路。
- 窗口加载链路排查应先使用静态诊断页，不挂载截图遮罩组件。
- 如果静态诊断页也白屏，后续诊断只能在主窗口内展示，不再创建新的子窗口入口。
- 如果透明背景或全屏置顶在 Windows 11 上出现白屏、黑屏、无法关闭等异常，必须立即暂停截图入口。
- 原生 Win32 框选层顶部提示只在尚未开始拖拽前显示；拖拽过程中不持续绘制顶部提示，避免提示条闪烁。
- 原生 Win32 框选层绘制应使用双缓冲或等效方式，避免鼠标拖拽时整层闪烁。

## 5. 截图预览窗口

截图完成后显示预览窗口。

要求：

- 图片比例正确。
- 不拉伸变形。
- 大图需要适配屏幕尺寸。
- 预览窗口右下角显示横条菜单。

菜单按钮：

- 复制。
- 翻译。
- 提取。

首版不做标注工具，不做贴图，不做保存到文件。

截图横条菜单视觉：

- 使用和设置页一致的浅色玻璃胶囊栏。
- “复制、提取、翻译”使用统一浅色玻璃按钮样式，不单独突出“复制”。
- 菜单不得使用互相割裂的深色块或紫绿色杂色按钮。
- 菜单外框只能有一个圆角玻璃壳层，不得出现类似两块面板重叠的阴影或底板。
- 按钮 Hover/Pressed/松开反馈应与设置面板按钮一致，不产生滑动位移。
- 框选完成并显示菜单后，鼠标指针应从十字框选光标恢复为普通箭头。
- 截图提示、框选边框和截图菜单必须跟随软件主题；深色主题下使用中性黑灰横条和灰白框线，避免蓝白菜单突兀出现。

## 6. AI 结果弹窗

结果弹窗用于展示：

- 文本翻译。
- 文本总结。
- 图片文字提取。
- 图片文字翻译。

结构：

- 顶部标题；翻译结果窗口不显示左上角标题，顶部只保留居中的语言方向控件。
- 右上角固定显示图钉按钮和关闭 `×` 图标按钮。
- 内容区域。
- 底部操作区右下角只保留“复制”按钮。

操作：

- 复制结果。
- 点击右上角图钉固定/取消固定置顶，固定态必须有明确高亮或形态区分。
- 图钉图标使用简化空心轮廓：顶部短横帽、两侧斜肩、底部横边和中间短针，不使用斜插针或复杂实心图形。
- 点击右上角 `×` 关闭。
- 翻译结果顶部显示“源语言、方向按钮、目标语言”三段控件，例如 `英文 → 中文`。
- 翻译结果顶部三段控件应水平居中，不贴右侧。
- 源语言和目标语言均可通过下拉列表选择；源语言可使用“自动检测”。
- 方向按钮支持单击切换方向，例如 `英文 → 中文` 切换为 `英文 ← 中文`，并在同一个结果弹窗内重新显示 Skeleton 和更新译文。

要求：

- 内容过长时可滚动。
- 内容滚动时必须被内容框裁剪，文本不得越过内容框边界或覆盖底部按钮区。
- 保持紧凑，不占满屏幕。
- 错误信息必须清楚。
- 成功态不显示“请求已完成。结果仅保存在当前内存状态中，清空后不再保留。”等底部完成说明；只在错误、配置缺失或排障状态显示必要提示。
- 未固定时点击窗口外部、空白处或 `Esc` 应可销毁窗口。
- 固定后应保持在最前面，且失焦不自动关闭。
- Loading 状态使用带扫光动效的 Skeleton 骨架屏，不显示“正在处理”类正文提示，也不显示底部保留策略说明。
- 结果从 Skeleton 更新为最终文本时需要有轻量淡入或位移收敛动效，不得突然闪现。
- “复制”按钮和右上角图标按钮应与设置面板按钮保持一致：Hover 有颜色和阴影反馈，Pressed 只在按住期间轻微居中缩小和加深颜色，松开后复位，不产生滑动位移。
- 结果窗口按钮 Hover、Pressed 和 Skeleton 动画刷新不得造成整窗闪烁；优先使用局部刷新和双缓冲绘制。
- 结果弹窗必须跟随软件主题；深色主题下窗口背景、内容框、按钮、文字和 Skeleton 骨架屏都使用设置页同款中性黑灰层级。
- 翻译结果语言下拉不得使用系统原生菜单；应在结果弹窗内自绘，浅色主题下使用蓝白玻璃面板、清晰边线、低透明度背景和统一按钮高亮，避免出现与软件风格割裂的系统菜单。

## 7. 设置窗口

设置窗口包含：

- 通用设置。
- 快捷键设置。
- AI 设置：文本模型和视觉模型必须拆成两个独立卡片。
- 外观设置。
- 隐私说明。

快捷键设置：

- 不使用手动文本输入框。
- 使用点击后直接按组合键的快捷键捕获控件。
- 捕获期间提示“请直接按下新的快捷键组合，Esc 取消”。
- 捕获到有效组合后自动写入设置值，仍需点击“保存设置”后才持久化并重新注册。
- 捕获期间应临时忽略当前全局快捷键，避免录制 `Alt+3` 时触发截图。

外观设置首版选项：

- 主题：跟随系统、浅色、深色。
- 窗口效果：仅 Mica，不提供其他窗口效果入口。
- 主题选择应立即反映在设置页视觉上；保存后重启仍保持。
- 窗口效果只作用于预创建的 `main` 设置窗口；不可为了验证效果创建新的 WebView 子窗口。
- Mica 不可用时必须降级为可读的半透明或实色背景。
- 默认视觉目标采用 Frosted Glass：透明窗口底、半透明玻璃壳层、柔和高光边线、轻阴影、冷调蓝色强调色。
- 参考 TieZ Frosted Glass 只复刻视觉气质和交互层级，不直接复制 GPL 源码片段。
- 深色 Frosted Glass 不应表现为大块实心深蓝面板，应保持半透明层次、可见边线和柔和高光。
- 深色主题应参考现代 AI 编程工作台：近黑石墨背景、深灰导航、略浅编辑区和卡片表面、1px 细边框、克制阴影、紧凑信息布局；激活态使用低饱和蓝色或青色，成功使用柔和绿色，警告使用琥珀色，错误使用红色。
- 深色主题不得使用明亮渐变、装饰插画、强光泽、过大卡片或营销式首页布局；圆角保持 `6-8px`，界面字体使用 `"Segoe UI", "Inter", sans-serif`，代码或终端内容使用 `"JetBrains Mono", "Cascadia Code", "SF Mono", monospace`。
- 深色主题必须同时作用于设置页、划词菜单、截图菜单、托盘右键菜单和原生结果弹窗，避免 Web 设置页与原生弹窗割裂。
- 深色主题下“保存设置”按钮保持与浅色主题相同的蓝色主按钮样式，以突出窗口级保存动作；其他普通控件继续使用石墨灰工作台样式。
- 设置页应使用自定义玻璃标题栏，标题栏按钮风格必须与页面控件一致；关闭按钮只隐藏设置页，不退出托盘常驻进程。
- 自定义标题栏右侧最小化、最大化、关闭按钮需保持接近 Windows 标准标题栏的视觉尺寸和点击热区，不得因玻璃风格缩小成小号控件。
- 如果使用自定义标题栏，Rust 显示设置窗口前必须运行时关闭系统装饰，前端加载后也应兜底确认，避免系统标题栏和自定义标题栏同时出现。
- 设置页卡片阴影应柔和，不得出现生硬厚重投影。
- 设置页卡片内按钮应具备 Hover、Pressed 和松开复位三种反馈；按钮动效不得产生位置滑动，只允许颜色、阴影和轻微缩放变化。
- 设置页选择器应使用自定义玻璃下拉控件，不使用浏览器原生下拉菜单。
- 设置页选择器下拉列表必须使用页面级浮层，层级高于卡片和滚动容器，不得被下方卡片遮挡或裁剪。
- 设置页选择器下拉列表背景透明度必须足够低，底层文字不得透出影响可读性。
- 设置分类导航不得使用页面锚点导致整个窗口滚动；点击导航只滚动设置内容区，顶部标题和状态面板不得被遮挡。
- 设置分类导航的选中态应使用独立浅蓝色圆角滑块直接移动到目标按钮，不得在滚动过程中依次点亮中间按钮。
- 设置分类导航需要区分 Hover、选中和 Pressed：Hover 保持浅蓝提示并略微浮起，选中态颜色更深更稳，Pressed 只在按住时略微缩小、下沉并加深颜色。
- 设置分类导航点击时滑块应在按下阶段开始移动，并在普通点击松开前基本到位。
- “保存设置”是窗口级操作，应固定在设置窗口右下方常驻，不放入 AI 配置卡片，也不随内容滚动消失。
- 设置页头部卡片在浅色和深色主题下必须使用同一套几何规格：`84px` 最小高度、`15px 18px` 内边距、`14px` 间距、eyebrow `12px` 字号和 `7px` 下间距、标题 `25px` 字号和 `1.08` 行高；浅色 eyebrow 与深色一致使用 `var(--qp-accent)` 强调色。
- 设置页所有卡片在浅色和深色主题下必须使用同一套几何规格：窗口网格间距 `8px`、布局间距 `10px`；导航条 `46px` 最小高度、`7px` 内边距、`4px` 间距，导航按钮 `30px` 最小高度、`6px 10px` 内边距、`13px` 字号；分节列表间距 `9px`、右内边距 `6px`，分节卡片 `14px` 内边距，分节标题 `18px` 字号、`8px` 下间距、`1.2` 行高；设置列表间距 `0`，设置行 `9px 0` 内边距、`6px` 间距、无最小高度；输入框、下拉触发器和快捷键捕获框 `34px` 最小高度、`7px` 圆角；保存栏 `54px` 最小高度、`9px 10px` 内边距、`8px` 间距、`10px` 下外边距，保存按钮 `38px` 最小高度、`0 18px` 内边距。仅几何统一，配色仍按主题各自变量。
- 设置页头部“QuickPick 核心已连接”状态胶囊在浅色和深色主题下大小和位置必须一致：固定 `30px` 高、左右 `10px` 内边距、`12px` 字号、`1` 行高、`13px` 上外边距和 `13px` 右外边距，相对头部面板的上偏移 `28px`、右偏移 `31px`。
- 状态胶囊配色按主题使用半透明绿色玻璃，不使用实色：浅色为绿白玻璃（`rgba(var(--qp-success-rgb), 0.1)` 底、`rgba(var(--qp-success-rgb), 0.28)` 边、`var(--qp-success)` 文字），深色沿用 `rgba(111, 202, 154, …)` 绿色玻璃和 `#d8f2e3` 文字；两主题共用 `--qp-success-rgb` 半透明主题变量体系。

设计原则：

- 信息密度适中。
- 使用表单、开关、选择器，不用花哨卡片堆叠。
- API Key 输入框默认隐藏明文。
- 保存成功有轻量反馈。
- 错误配置必须就地提示。
设置入口：

- 应用启动后默认静默，不显示主页面。
- 设置页只通过托盘右键菜单“设置”显示。
- 设置页复用预创建的隐藏 `main` 窗口，不创建独立 `settings` WebView 子窗口。
- 设置页标题使用“QuickPick 设置”，关闭按钮只隐藏窗口并保持托盘常驻。
- 启动或设置打开时不得出现浏览器式 `127.0.0.1` 无法访问页面。

## 8. 托盘菜单

托盘右键菜单包含：

- 设置。
- 自启动。
- 退出。

菜单文字保持简短。

托盘交互：

- 双击托盘图标打开设置页。
- 右键菜单里的“自启动”必须是可勾选开关，只通过菜单项前面的勾选标记表示开启/关闭，状态和设置页一致。
- 托盘右键菜单使用原生 Win32 自绘小弹窗，不创建 WebView 菜单；菜单需跟随软件主题，浅色为白色玻璃面板，深色为石墨黑工作台面板。
- 托盘右键菜单面板应保持紧凑，默认宽度约 `140px`，只显示三行短文案。
- 托盘右键菜单文字使用和其他原生弹窗一致的 `Segoe UI` 常规字号，避免字号割裂。

## 9. 图标规范

图标方向：

- QuickPick 图标应体现“快速拾取”的产品含义，以“四角框选括号 + 三行文本线”的线性图形为核心符号。
- 可参考 Codex 的安静、几何、低噪声科技气质，但不得直接复制 Codex 官方图形、比例或品牌标识。
- 主应用图标使用浅蓝紫渐变粗圆角矩形背板、顶部多段玻璃高光和纯白线性图形，保证开始菜单、窗口标题栏和浅色任务栏中都可识别。
- 图形应抽象简化：仅保留四角框选括号和三行文本线，不使用阴影、角向边缘光或复杂装饰。
- 新图标体系以“四角框选括号 + 三行文本线”的线性图形为核心符号，对应区域截图和划词两个核心动作；主应用图标为 E 套（已验收）：粗圆角矩形背板、五段式浅蓝紫渐变（顶部薰衣草 `#D2C7FC` 到底部蓝紫 `#2E4FE0`）、多段高光（柔光云和顶部高光斑收缩在顶部边缘，不遮挡中央白色图形）、虚化内边、纯白线性图形，不使用角向边缘光和深色底边。
- 托盘图标使用纯白线性“四角框选括号 + 三行文本线”图形（D 套），无背板、无阴影、透明底，贴合 Windows 11 深色托盘的单色工具气质。
- 托盘图标图形占画布约 92%（括号范围 11-117、括号线宽 12、文本线线宽 11），文本线与括号保持原始比例关系（线长约为括号跨度的 46%/58%/35%），与系统托盘其他应用图标的视觉重量一致。
- 设置页自定义标题栏小标记跟随主图标体系：渐变圆角方块接近满幅（约占画布 94%），内部白色图形占约 70%，18px 下清晰可读；托盘图标单独使用纯白线性版本。

资源要求：

- 可编辑源稿放在 `src-tauri/icons/source/`。
- 应用打包图标使用 `src-tauri/icons/icon.ico` 和 `src-tauri/icons/icon.png`。
- 托盘运行时图标使用 `src-tauri/icons/tray-icon.png`，该文件为纯白线性托盘图标。
- 不保留彩色版托盘图标，避免后续混用。
- 生成脚本放在 `tools/generate-quickpick-icons.ps1`，不得联网或引入额外 npm/Cargo 依赖。

## 10. 文案规范

文案要直接，不解释过多技术。

示例：

- “未读取到选中文本，请重新选择后再试。”
- “API Key 未配置，请先到设置中填写。”
- “当前模型可能不支持图片识别，请检查视觉模型配置。”
- “已复制。”

避免：

- 长篇说明。
- 技术堆砌。
- 模糊错误，例如“失败了”。

## 11. 可访问性和易用性

- 所有关键操作应支持键盘关闭，例如 `Esc`。
- 图标按钮应有 tooltip 或 aria-label。
- 文本不能溢出按钮。
- 结果内容应可选择复制。
- 高 DPI 下 UI 不能模糊。
- 深浅色主题下对比度必须足够。
