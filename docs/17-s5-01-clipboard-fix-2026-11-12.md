# S5-01 截图复制修复与复测

日期：2026-11-12（Asia/Hong_Kong）。对应 [阶段 5 原始报告](16-windows-stage5-2026-11-11.md)。S5-01 修复范围已在 [fix2 Windows 复测](18-windows-fix2-retest-2026-11-12.md)通过：52 项测试、九次真实双格式回读与指定合成图的 GUI 复制、Release/热键/重新打包均有证据。阶段 5 全量验收仍未通过。安装升级继续等待可还原的隔离环境，不覆盖正式安装。

## 原因与改动

报告中的不透明合成图直接调用 `probe::copy_image` 即失败，RGBA32/V4 与 RGB24 对照明确，不依赖截图、Chrome、选区移动或 CF_DIB 写入顺序。

`clipboard-win 5.4.3` 的 `set_bitmap_with` 只复制固定 BITMAPINFOHEADER 再交给 CreateDIBitmap，无法完整传递当前 RGBA BMP 的扩展头与通道掩码。旧编码回归检查得到 108 字节信息头；现在明确转为 RGB24，再以 BI_RGB 的 40 字节信息头编码。

- 新增独立 `bitmap::encode_clipboard_bmp`，真实 `copy_image` 使用同一函数；CF_DIB 与 CF_BITMAP 写入链保持原状。
- RGB 通道直接保留，忽略桌面截图的 alpha，不做预乘或背景混合。宽高、行顺序和颜色不改动；不新增 PNG 编码或 AI 上传。
- 图片转换与剪贴板操作仍在原后台工作任务内。进入/拖动/取消遮罩不捕获的边界不变。
- 未升级 image/clipboard-win，未更改根 Cargo.lock 或截图交互。仅增加已有 image 版本的 BMP 开发测试依赖，以便 Linux 执行纯编码测试。
- 同步报告中的 Windows PowerShell 5.1 工具兼容：显式加载 System.IO.Compression；JSON 先赋值再转换数组，函数显式枚举对象，避免嵌套数组。增加多条第三方声明夹具。

## 已通过复测的合并与命令参考

修复包提供完整 `snapshot` 和只改平台模块的 `S5-01.patch`。已有 fix1 工程可以保留本机验收夹具，先检查再应用：

```powershell
git apply --check "解压目录\S5-01.patch"
git apply "解压目录\S5-01.patch"
```

首个命令失败就停止，不强制覆盖。若使用全新 snapshot，可原样复制本机 `full_acceptance.rs` 后运行原失败断言与全部测试。阶段 5 脚本若已在本机修正，不重复覆盖；本包提供的工具脚本包含修正和新增夹具。

先验证真实剪贴板函数。下面的显式命令会把剪贴板替换成合成测试图片，请在 GUI 截图复测之前运行，避免用合成结果冒充真实截图：

```powershell
cargo run -p quickpick-platform --example verify_clipboard_image --locked --target-dir target/gpui-candidate -- --replace-clipboard-with-synthetic-image
```

example 连续三轮、每轮三种尺寸调用真实 `probe::copy_image`，分别读取 CF_DIB/CF_BITMAP，并检查解码后的每个 RGB 像素与尺寸；输出仅通过/错误状态。不捕获屏幕、不读取密钥、不联网、不写图片文件。不带显式替换标记时退出；普通 cargo test 不执行这个剪贴板操作。

随后构建并启动修复候选：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-gpui.ps1 -Launch
```

在原合成动态页面中通过 GUI 框选并明确点击“复制”：确认不再出现“写入位图失败”，剪贴板图片尺寸/颜色/方向正确，输出不含暗化、边框或工具栏；逐项记录八向缩放、Enter 保持遮罩、取消不改变剪贴板。粘贴或像素检查只在内存中处理合成画面，不保存实际截图。合成回读 example 成功不能代替这些 GUI 结论。

正常退出候选后重新执行 `scripts/build-gpui.ps1 -Package`、热键检查和包静态校验。原 fix1 EXE/ZIP/NSIS 哈希不能用于本修复版本。
