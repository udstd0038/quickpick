# QuickPick 开发路线

## 开发原则

- 一次只推进一个小阶段。
- 每个阶段必须有可运行或可检查的验收点。
- 不在未验证基础能力前堆 UI 和扩展功能。
- 不提前加入滚动截图、标注、贴图、历史记录等非 MVP 功能。
- 每次开发结束必须更新当天开发日志。

## 第 0 阶段：文档与流程基建

目标：

- 创建项目目录。
- 创建 `docs/` 标准文件。
- 创建 `dev-logs/` 开发日志目录。
- 创建 `CLAUDE.md` 工作说明。

验收：

- 所有标准文档存在。
- `CLAUDE.md` 能指引后续开发者先读规范、再开发、后记录。
- 当天日志记录本阶段完成事项和下一步待办。

## 第 1 阶段：Tauri 2 空项目骨架

目标：

- 初始化 Tauri 2 + Rust + React + TypeScript + Vite 项目。
- 创建最小可启动窗口。
- 添加系统托盘占位。
- 添加设置窗口占位。

建议任务：

- 初始化 `package.json`、`src-tauri/`、`src/`。
- 确认 Windows 本地开发命令能启动。
- 注册托盘图标和基础右键菜单：打开设置、退出。
- 建立前后端通信示例命令。

验收：

- 本地能启动应用。
- 关闭主窗口后应用仍可托盘常驻。
- 托盘菜单能打开设置窗口并退出应用。

## 第 2 阶段：全局快捷键与划词 MVP

当前状态：

- 白窗问题排查完成前，`Alt+2` 和托盘“划词弹窗”不再创建 Tauri/WebView `selection_bar` 子窗口。
- `Alt+2` 会读取当前选中文本，然后打开原生 Win32 划词弹窗。
- 原生划词弹窗提供复制、搜索、翻译和总结。
- 文本翻译和总结结果显示在原生 Win32 结果弹窗，不创建 Tauri/WebView `result` 子窗口。
- 原生结果弹窗支持关闭、点击外部销毁、复制结果和固定置顶。
- `selection_bar` 和 `result` 的 WebView 创建入口已撤回，仅保留前端静态分支作为后续恢复参考。

目标：

- 注册默认快捷键 `Alt+2`。
- 选中文本后按快捷键呼出横条菜单。
- 完成复制与搜索。
- 再接入文本翻译和总结。

建议任务：

- 接入 Tauri global-shortcut 插件。
- 创建划词菜单窗口，设置为轻量、无边框、置顶、失焦隐藏。
- 实现读取当前选区文本。
- 实现复制文本到剪贴板。
- 实现默认浏览器搜索。
- 实现文本 AI 请求和结果弹窗。

验收：

- 在记事本、浏览器、常见编辑器中选中文本后可呼出菜单。
- 当前安全阶段允许先用原生 Win32 弹窗实现无感划词，最终 Tauri/WebView 横条菜单待白窗问题解决后再恢复。
- 复制不会意外破坏原剪贴板。
- 搜索能使用默认浏览器打开。
- AI 失败时不会卡住界面。

## 第 3 阶段：区域截图 MVP

当前状态：

- `Alt+3` 已切换为原生 Win32 框选区域截图；托盘截图和主窗口截图按钮入口已撤回；Tauri/WebView 全屏遮罩仍因白屏锁定问题暂停。
- 普通“截图安全预览”窗口也出现白窗且无法关闭，入口已撤回。
- 静态 `window-diagnostic.html` 子窗口也出现白窗且无法关闭，入口已撤回。
- 普通 `settings` 窗口也出现白窗且标题栏、任务栏均无法关闭，验证入口和托盘设置入口已撤回。
- 当前改为只在主窗口内显示诊断面板，不再创建新的诊断子窗口。
- 主窗口诊断面板已扩展显示 capability 窗口列表、构建资源状态、子窗口配置对照、窗口创建链路风险对照、前端窗口识别分支对照、视图初始化副作用对照、视图错误态兜底对照、构建产物加载关系对照、`settings` 失败撤回记录、子窗口 WebView 创建失败原因对照、配置权限与插件链路核对、capability 授权精简执行状态、Snow Shot 截图链路审计状态、Snow Shot 窗口创建与关闭链路审计、Snow Shot 非窗口截图核心候选审计、Snow Shot 截图依赖许可证审计、只读截图命令草稿实施方案、最小截图依赖引入与扫描方案、传递依赖扫描执行方案、许可证扫描工具选择与离线替代方案、最小截图依赖引入状态、原生区域截图剪贴板 MVP 和已撤回入口风险清单。
- 白窗问题排查完成前，不再开放任何会创建 Tauri/WebView 子窗口的主窗口验证按钮、托盘设置入口、截图预览窗口或诊断子窗口入口。
- 当前高概率排查方向仍是动态 `WebviewWindowBuilder` 创建、子窗口 WebView 初始化、capability 或 window-state 交互；不过划词和结果链路已先改为原生 Win32 弹窗，避免继续依赖 WebView 子窗口。
- 多余 capability 授权精简方案已人工确认，`src-tauri/capabilities/default.json` 已临时精简为仅授权 `main`。
- 后续恢复 `settings`、`selection_bar`、`result` 或 `screenshot_overlay` 前，必须先补回对应 capability 授权并单独验证。
- 截图实现策略已调整：放弃继续自研截图核心实现，优先按 `docs/07-reference-migration-spec.md` 从 Snow Shot 可用截图链路中合规复刻或移植。
- 引入任何 Snow Shot 代码前，必须先完成许可证、来源 commit、文件清单、复用边界和回退方案记录。
- Snow Shot 截图参考实现初步审计已记录在 `docs/08-snow-shot-screenshot-audit.md`，当前已基于 `xcap + image + clipboard-win + windows-sys` 完成原生区域截图和横条菜单 MVP。
- `Alt+3` 会打开原生 Win32 临时框选层；拖拽后显示“复制、提取、翻译”横条菜单。
- “复制”写入系统剪贴板；“提取”和“翻译”在 AI 配置完整时调用 OpenAI 兼容视觉模型，并把结果显示在独立原生 Win32 结果弹窗内。
- 截图预览窗口和 Tauri/WebView 截图遮罩仍暂停，避免再次进入白窗和不可关闭链路。

目标：

- 注册默认快捷键 `Alt+3`。
- 完成原生区域截图框选、横条菜单、复制图片、OCR 提取和图片翻译入口。
- 后续再恢复截图预览窗口。

建议任务：

- 对 Snow Shot 截图模块做许可证和源码结构审计，确定可复刻范围。
- 只移植区域截图、预览和复制图片所需的最小链路。
- 实现多显示器和 DPI 基础兼容。
- 验证不同视觉模型对 OpenAI chat/completions 图片输入格式的兼容性。
- 在 Tauri/WebView 子窗口问题解决后，再创建截图预览窗口。

验收：

- 能在 Windows 11 上拖拽选择区域，松开后看到横条菜单。
- 点击“复制”后能把所选区域图片粘贴到画图、微信或文档。
- 点击“提取”或“翻译”后，配置不完整时独立原生结果弹窗显示明确提示，不读取截图或发起 AI 请求。
- AI 配置完整时，点击“提取”或“翻译”会在独立原生结果弹窗显示 OCR/翻译结果。
- 主窗口 AI 配置拆分为文本模型和视觉模型两组：文本模型支持通用 OpenAI 兼容、DeepSeek、小米 MiMo、Kimi、GLM、MiniMax 和 Qwen；视觉模型支持通用 OpenAI 兼容、小米 MiMo、Kimi、GLM、MiniMax 和 Qwen。
- DeepSeek 恢复为仅负责文本模型；截图 OCR/翻译使用独立视觉模型配置和独立 API Key。
- Esc、右键或 60 秒超时能退出原生框选层。
- 点击复制后可以粘贴到微信、画图或文档。

## 第 4 阶段：OpenAI 兼容 AI 能力

目标：

- 支持 OpenAI 兼容配置和供应商预设，包括文本模型与视觉模型的独立供应商、Base URL、模型名称和 API Key。
- 完成文本翻译、文本总结、图片 OCR、图片翻译。
- 统一结果弹窗和错误处理。

建议任务：

- 主窗口内安全配置区增加文本模型和视觉模型两组 `provider`、`base_url`、`model`、`api_key`，并增加翻译语言设置。
- Rust 或前端实现统一 AI client。
- 文本功能使用 text model。
- 图片功能使用 vision model。
- 增加超时、取消、错误提示。

验收：

- 可接入 OpenAI 兼容服务。
- 文本翻译和总结输出简体中文。
- 图片 OCR 能提取截图中文字。
- 图片翻译输出原文与译文。
- 无 API Key、Key 错误、网络错误、模型不支持图片时均有提示。

## 第 5 阶段：设置、安全与体验打磨

目标：

- 完成设置持久化。
- 完成 API Key 本地加密保存。
- 完成开机自启。
- 完成快捷键映射。
- 完成暗黑模式和 Win11 窗口效果降级。

建议任务：

- 接入 Tauri store 或自定义配置文件。
- API Key 使用 Windows 本地加密能力保存。
- 接入 autostart 插件。
- 设置页支持修改快捷键并重新注册。
- 设置页支持主题：跟随系统、浅色、深色。

验收：

- 重启应用后设置仍存在。
- 修改快捷键后立即生效。
- 开机自启开关状态准确。
- Windows 11 上 Mica 可用时启用，不可用时自然降级。

## 第 6 阶段：验收与打包

目标：

- 按测试文档逐项验收。
- 修复阻塞问题。
- 打包 Windows 安装包或便携包。

验收：

- 所有 MVP 功能在 Windows 11 上通过手动验收。
- 没有明显崩溃、卡死、窗口残留。
- 常驻状态无明显 CPU 占用。
- 打包产物能在干净 Windows 11 环境启动。
